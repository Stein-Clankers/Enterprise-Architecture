# Archipelago

Open-source Enterprise Architecture repository that runs entirely in the browser: a static web app on GitHub Pages, all data local. ArchiMate 3.2-native core, LeanIX-class portfolio surface. This is the product repo; the research that motivated it (*EA for the Agentic Organisation*) is preserved at the `knowledge-base-final` tag.

## Stack

TypeScript (strict) · React · Vite · Vitest · React Flow (@xyflow/react) + ELKjs for generated views · idb (IndexedDB persistence) · GitHub Actions → GitHub Pages. No backend. No runtime CDN fetches — fonts and all assets are self-hosted.

## Critical conventions

- **Design tokens are law.** `src/styles/tokens.css` is copied verbatim from the design handoff and is the single source of colour. Zero border-radius on boxes, controls, and surfaces — drawn circular *glyphs* (theme toggle, search circle, phase dots) are exempt; no shadows (one exception: command palette); hairline borders. The semantic ramps (layer / lifecycle / TIME) are the report legend, not decoration.
- **Monospace marks machine-readable content** (ids, counts, property keys, type codes, relation types); Space Grotesk for human-authored content. This split is intentional identity — see the UI spec §2.1.
- **Lifecycle is derived, never stored.** Elements carry phase dates; the phase is computed at a time point (UI spec §3.1). Do not add a stored phase field.
- **Relationship properties are first-class.** Costs, support type, CRUD usage, validity dates live on edges (ADR 0001). Never demote them to element fields.
- **Canonical JSON is deterministic:** sorted keys, stable IDs, byte-identical export→import→export (ADR 0004). Anything that breaks this breaks git-friendliness. Locale-dependent ordering is banned by lint rather than by memory: `localeCompare` and `Intl.Collator` fail ESLint unless the locale is a **string literal at the call site** — `undefined`, `void 0` and a variable all reach the machine's locale, and only the literal is something a selector can see. `src/test/eslint-rules.test.ts` drives the rule and its bypasses.
- **Import/export never drops data silently.** Anything a read or write cannot carry — unknown types, malformed fields, duplicate ids, views, unrecognised keys — surfaces as an `ImportProblem`. Silent loss is a bug even when the data is "ours". **A reader ignores by omission, so a test of what it reports cannot see what it never looked at:** so both XML readers keep a `Ledger` (`src/io/consumption.ts`) and every attribute or child element left unmarked is reported as `import.content-unread` (#101). **Mark a key where its value lands in the model or in a problem, not where you fetch it:** a value read and then discarded must stay unread. **Count an object in a report's tally only once it is kept:** readers read before they find a duplicate id, so a count taken at read time includes what was skipped (#106, #114, then four tallies in #123). A key ignored on purpose goes in the reader's `IGNORED`, with its reason. **A fixture that says it is a tool's output must be written by that tool:** a hand-edited `.archimate` holds what you think Archi writes. As a line of text this did not hold — #100's re-save with Archi found three reader bugs behind one hand-written fixture (untyped lines, `<bendpoint/>`, `lineAlpha` as a feature) — so `fixture-provenance.test.ts` now fails on any spelling Archi's serializer never produces; re-save with `scripts/fixtures/export-with-archi.sh`, never patch the file. **An oracle's reason for a difference is a predicate on the value the tool produced, not on its type:** a reason that accepts any number explained every font size where Archi writes one measured default (#139, again #186). (Harvested from the #17 review, where 7 of 15 findings were this pattern, again from #98: 9 silent drops behind a test that pinned every reported code, and from #100.)
- **Never join user-authored strings with a separator and no escaping.** Names, tag labels, property keys and *ids* may contain any character, including your delimiter. This covers serialised formats (exchange-format tag lists, URL facet params, CSV) **and any string you compare for equality** — a cache key, a memo key, a dedupe set. Each needs escaping and a round-trip test using a value that *contains* the separator — **and one that looks like your escaped form**, because the decoder has to be unambiguous too, **and one where the escape of the next character supplies the closing delimiter** (#216: `_x0041` followed by a control character was written `_x0041_x0001_` and read back as `A…`). **The read side has the same trap: `record[key]` with a key somebody else chose finds `Object.prototype`'s members,** so a lookup by id goes through `Object.hasOwn` (a `getKey` beside `setKey`), and the rollout fixture carries a key named `constructor` so every consumer meets it (#229: a milestone labelled "Constructor" blanked the rollout screen after its command was saved, and every later open crashed). (Harvested five times: comma-joined tags in the #17 exchange writer, the identical bug reintroduced in #26's `?facets=` encoder, #27's `+ tag` prompt making the first one reachable from the UI, #28's `shapeKey` joining element ids with `,` to decide whether to re-run layout, then #37's fix for the first one — a JSON-array encoding detected by a leading `[`, so a tag literally named `["a"]` decodes to `a`.)
- **The model's type guards belong on the write path, not just the read path.** `isFitLevel`, `isTimeClassification` and friends exist because the importer needs them — a `<select>`'s empty option is the same untrusted input. `Number('')` is `0` and `'' as TimeClassification` compiles, so a "clear this field" control silently stores a value the published JSON schema rejects and the exchange writer then drops. Anything turning a form value into a model type goes through the guard and yields `undefined` when it fails. (Harvested twice: `annualCost` in `profile-properties.ts`, then #27's assessment selects.)
- **All model mutations go through the command stack** (undo/redo + dirty counter). No direct store writes from UI code.
- **A write a writer opened must not outlive the role becoming reader.** Every route renders for a shared-folder reader (`role` is `'reader'` when someone else holds the lock, ADR 0010). Since #198 the store refuses every write from a reader (`ReadOnlyModelError`), so a missed guard can no longer write, but it still shows a reader a field or dialog whose commit throws and loses what they typed. So a guard on the *button* that opens a dialog or edit mode is not enough: end the mode when the role becomes reader (an effect on `role` that clears the flag, so it does not reopen when the tab writes again), and test the switch to reader while it is open, as well as the reader render. **A field that commits on blur also renders on the role** (`editingOpen && !readOnly`): the effect alone leaves one commit with the role reader and the field on screen, and a refused save's dialog takes focus in that commit, blurring it into a write; `TakesFocusAsReader` (`src/test/`) is that dialog in a test. **Nothing may write in an effect cleanup as a reader:** a throw in React's commit blanks the app, which has no error boundary (#204's view panel saved typing on unmount). `renderScreenAs` (`src/test/render.tsx`) gives a test the role, through the real `FileWorkspaceProvider`. (Harvested from #192's Edit button, filed as #195, then #197's fact-sheet Delete dialog, which deleted the element after the role had become reader, then the #200 and #204 reviews.)
- **When a route parameter identifies the subject, key the component on it.** `/element/:id` re-renders without remounting, so anything holding per-subject state — a memo, `defaultValue` on an uncontrolled input, an `editing` flag — silently carries the previous subject's data onto the next one. `key={id}` makes the whole class impossible; a `useEffect` that resets state is the version you have to remember to extend. (Harvested from #27, where one root cause produced a stale selector, an edit form that overwrote the element you navigated *to*, and a test that could not fail.)
- **Move focus only in answer to a user action, and only as that action ends.** Enter, Escape, or a button whose action unmounts it hands focus to the canvas or the next field. **Never on `blur`:** a blur *is* the user putting focus somewhere, and taking it back steals their next key (#144: committing a name on blur focused the canvas, and Backspace in the field the user had clicked deleted the new shape). **Never in a mount effect of a component keyed on changing data:** `key={name}` re-runs "first mount" on every rename (#144's view-name field took focus back after each one). **A modal's backdrop is `DialogOverlay` (`src/ui/common/`), and lint rejects a hand-made one (#157):** it prevents the default of the press that dismisses, which otherwise runs after your restore, finds nothing focusable where the overlay was, and focuses `<body>` (#156: a press outside the nesting prompt blurred the name field the answer had just opened). An action that unmounts what holds focus needs a test that says where focus lands, **and a hover is such an action** (#181: hovering a menu's other entry swapped the column holding focus, which fell to `<body>`): removing that code left every test green in #142, and again in #144. **Arming a mode puts focus where its keys are handled:** #186's format painter said "Escape stops" and left focus on the button that armed it, where Escape reaches no handler.
- **A fallback, a timeout or an error branch needs a test that fires it.** Resilience code is the least exercised code in the repo and the most likely to be wrong: it only runs on the day something else already went wrong. If a PR adds one, a test must drive it. **In `src/io/shared-folder/` this is mechanical:** `npm run test:coverage`, which CI runs, fails below 100% of branches, functions, lines and statements there, counting files no test imports (#164, after #161 shipped nine untested branches). A `/* v8 ignore */` there needs its reason after `--` (`coverage-gate.test.ts`), and a test is better. **That includes the fallback you didn't write on purpose:** `if (root?.local === 'model' && wrong) refuse()` skips the guard whenever `root` is undefined, so the input the guard can't classify is the one it lets through. **So does a guard that compares its result with its input:** `if (clamped !== value) report()` stays silent when the key is absent, because `undefined === undefined` (#187's legend `rowsPerColumn`). Test the absent key on its own. **An operand added to an existing condition is a new branch:** in `if (a.length || b.length)`, remove the new operand alone and run the suite (#217's site-only `<relationships>` block survived its removal across 241 tests). **A `switch` over a precision or a kind has one test per case, and the fixture must reach each case:** #223's `dayAfterPeriod` had its month branch pinned and its quarter and week branches pinned by nothing, because every fixture window ends in a month. **A rule applied with a sign is two cases:** #235's exact-day rule held for dates spaced forward and backward, and snapping only the backward ones (`gap < 0`) survived three forward tests. A precedence that holds "early or late" is such a rule: pin the winner on both sides of the date it beats (#235's actual-day precedence was tested only with a late actual, and `max(actual, spaced)` passed). Every check that reads a precedence pins both sides itself: a test that fails only when the shared helper breaks proves the helper, not the check (#242's dependency order). **A comparison of dates needs a fixture where the precisions disagree,** or a narrowing probe is a no-op: at day precision the actual day, the spaced day and a period's first and last day are one number, and #242's order checks survived four such probes. **A predicate over a set (`every`, `some`, "all of which") needs a fixture whose members disagree:** #242's "next wave" was tested only on waves whose sites start together, and `every` → `some` passed. **A `try … finally` without a `catch` is not such a branch** when nothing reachable throws past it and every statement in it runs on the success path (#205's import dialog); its comment says nothing throws today, and does not promise a throw it handles. A guard fails *closed* on input it can't read (#102 re-opened #99 that way, through a doctype with `[` in its system id). **A deadline is checked on every attempt, not only on a failed one:** #161's writer fenced itself after half the stale time only when a heartbeat *failed*, so a laptop that slept 40 minutes made no attempt at all, woke, succeeded once, and saved over a lock a colleague had already taken. **Then list what else reaches the closed branch:** placed ahead of an older check, it takes over every input that check used to diagnose, so its message must be true of all of them (#104's "parses as XML… please report this file" fired on an empty `.xml`; #205's catch for a file that cannot be read also caught a reader's crash and called the file unreadable). **The fix's own fallback is the next closed branch:** #205 then gave a failed read its own class and sent everything else to "a fault in Archipelago", which the file picker's own refusal (`NotAllowedError`, a site setting) reached next.. (Harvested from #28, which added a worker timeout, a worker-error channel, a main-thread fallback and a `?year=` guard, tested none of them, and was broken in all four — including a missing `.catch` that hangs the graph on "laying out…" forever. Vitest already exits non-zero on an unhandled rejection, so CI would have caught that one the moment a test made layout fail.)
- **A fake at the boundary tests the protocol, not the environment.** A stub `Worker`, a mocked `fetch`, a fake IndexedDB proves your *messages* are right and proves nothing about the code on the other side, because the fake runs in the caller's scope. Anything whose behaviour depends on **which globals exist** — `document`, `window`, `self` — needs a test that builds that scope, and a journey that opens the screen in a real browser. (Harvested from #54: `elk.bundled.js` decides it *is* the worker when `typeof document === 'undefined' && typeof self !== 'undefined'`, and in that branch exports no constructor, so the dependency graph failed in **every** browser while 467 jsdom tests and 15 e2e journeys stayed green. #28's fake `Worker` drove all six protocol branches and could not see it — jsdom defines `document`. The e2e harness names workers in its own docblock as what it exists to catch, and had no journey that opened the graph.)
- **Assert the presence before you assert the absence.** `toHaveCount(0)`, `not.toBeVisible()` and `queryBy… === null` are all satisfied by a page that has not finished rendering, so an absence asserted first is a one-sided bound wearing different clothes. Put it after something positive has landed. (Harvested from #54's own new journey, whose "no layout-failure alert" check passed against the fully broken graph and was caught only because the node count that followed it did not.)
- **A mechanical guard needs a test that fires it, and one for the nearest bypass.** **Guard the unit that can go wrong, not the file it lives in:** #160's tripwire listed the files that hold a key listener, so a new unguarded chord in a listed file passed, exactly as ⌘K had; and its regex saw `window.addEventListener` but not `globalThis.` or `onkeydown =`. A lint rule, CI check or type guard that silently fails is *worse* than no rule, because the next author trusts the line in this file that advertises it. When a review promotes a finding to a mechanical tier, the same PR proves it catches the original bug and the obvious way around it. (Harvested from #37, whose `localeCompare` rule — itself harvested from the #17 review to make ADR 0004 mechanical — errors on the bare call and passes `localeCompare(a, b, undefined)`, which collates by machine locale exactly as before, while the CLAUDE.md line it shipped with announced the guarantee.)
- **A test behind an acceptance criterion must fail when the feature is removed.** A green test is not evidence — *remove the feature and run the test*, which is cheaper than reasoning about it and is the only thing that settles it. **Remove one guard at a time:** in `open || isModalOpen() || …`, deleting the first two together passes on `open` alone and proves nothing about the second (#92's modal guard shipped untested that way), and a `finally` that does two things is two guards (#205 deleted the whole block to prove the test, and its input reset stayed untested), and a second call site of a fix is a guard of its own (#205's picker path "uses it too" survived being put back), and a predicate over a span is two guards, its start and its length: narrow the span to a point and run the test (#228's `touchesBlackout(d, d + freeze)` narrowed to `(d, d)` left 42 of 42 green); **and remove the call, not a helper it shares:** #181's `endGesture` guard and its render gate both called `magicSource`, so breaking the helper failed a test while deleting the guard left 37/37 green. **A case needs a subject that only the rule under test decides, whether it asserts that something happens or that nothing does, and a `.filter` is a guard:** #156's "within its container" moved a function the engine already had an Assignment to, so the existing-relationship rule kept the prompt shut, and deleting the within-container filter left every test green; #188's edge-snap test used two boxes of one width, so the centre rule, tried first, snapped them, and narrowing the edge threshold left the file green. **A criterion over a set of controls is a criterion on each one:** #186 proved "each change to a multi-selection is one command" for every control but Reset all. **A test or fixture builder that does what the screen does calls the screen's function, never a copy of its body, and never focuses by hand what the user's action should:** #116's group test and #185's oracle each rebuilt the canvas's wiring, so breaking that wiring left them green, and #186's Escape test focused the canvas itself, which hid that picking up the painter left focus on its button. **A fixture built in the order a sort produces cannot test the sort: reverse the input first** (#217's exchange-writer site sort survived its removal on a fixture that numbers its sites in order). Four recorded tells: a one-sided bound (`expect(n).toBeLessThan(150)` passes at 0); **two bounds that bracket the whole plausible range — `>0` with `<=100` asserts only that a percentage is a percentage**; a setup that rebuilds the very thing whose caching it means to test; **and a regex inside `toMatchObject`, which passes against any value because a RegExp has no own keys — lint rejects the spellings it can see (`archipelago/regex-in-to-match-object`, #177), and an equality tester in `src/test/setup.ts` fails the rest at run time (an `it.each` row, a loop variable, a parameter); write `expect.stringMatching(/…/)`**. **A colour an encoding promises is read off the computed style, against a sibling that must differ:** jsdom applies no stylesheet, so a class name or a `var()` proves only the selector (#223: an unscoped `.board__bar-fill { background: var(--lc-eol) }` painted every capacity bar red while 32 unit tests, two journeys and the author's own screenshots passed). **Text that a decision requires to be visible is read where it can be clipped:** `toHaveTextContent` passes on what an ellipsis hides (#235's "Standard (placeholder durations)" showed as "Standard (pla…"). A criterion that is satisfiable by inspection is still a criterion: prove it in a test, or it regresses silently (#24's "no layout shift when switching themes" was *met* and unprovable until `tokens.test.ts` asserted that the dark block redefines only colours). (Harvested from #25, #26, twice from #27, then #24 — five recurrences, so it is now also a lint rule: see #49. This sat in the review skill for three PRs and kept being broken by implementers, who do not read the review skill.)
- **A citation must be true of the text it labels: cite the page that states the fact, and read that page.** This holds for ADRs, the in-app guide and any doc. A page on the same topic is not a source, and a link is checked for what it serves *now*. Advice of our own is labelled as ours, not passed off as the source's. In the guide this is mechanical: `sources.ts` holds every cited work, and `guide.test.tsx` reads each citation off the page. (Harvested from #150, where ADR 0011 credited The Open Group's announcement with five facts it does not state, and from #153, where the guide's Cookbook link had come to serve a different book and several definitions said more than the specification's.)
- Work is issue-driven; every issue carries acceptance criteria — verify them before claiming completion. Branches: `feat/<issue#>-<slug>`.
- PRs are reviewed with `/review-pr <n>` before merge (stacked PRs bottom-up). Reviews harvest rules: recurring findings become lint/CI checks or a sharpened line here — if this file changed since your last session, re-read it.

## Constraints

- Nothing leaves the browser except file downloads the user initiates, or writes into a folder the user explicitly granted (ADR 0010: shared folders write models, lock files and their own audit log there, and nothing else).
- Browser storage is a cache; exported files are the source of truth. Never weaken or hide the save-state indicator, and **only mark the model clean on a write you can observe completing** — a fire-and-forget download is not one, and neither is loading a workspace that has only ever lived in IndexedDB. An indicator that overstates safety is worse than none. (Harvested from the #24 review: 4 of 15 findings were a write path claiming a success it cannot see.)
- The product name must not embed "ArchiMate" (Open Group trademark; ADR 0005). Keep the attribution line in the README.
- `design/handoff/` is a historical record — reference it, don't edit it.
- Pages serves from the `/Enterprise-Architecture/` base path; deep links must survive a hard refresh (404 redirect).
